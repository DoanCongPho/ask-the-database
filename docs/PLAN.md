# Plan: "Ask the Database": edit the Lovable frontend, then build the backend

## Context

The take-home asks for a web app where a non-technical shop owner asks a question, an LLM writes SQL, the app runs it read-only on PostgreSQL and shows the answer. The frontend now exists at `frontend/`, generated by Lovable from `docs/lovable_prompt.md`. Since then the user has changed direction:

- Shop owners aren't technical, so remove "Edit & run SQL" and let them refine an answer in plain language instead.
- Show the AI's reasoning steps in Vietnamese behind a button.
- For ambiguous questions, ask instead of guessing.
- Use a Vietnamese UI throughout.
- No RAG.

`docs/RESEARCH.md` (the user's scan of Snowflake Cortex, Databricks Genie, ThoughtSpot, Julius, AmbiSQL…) supports this: ambiguity is the #1 failure (P1), and answers that look right but are wrong are the main risk for non-technical users (P2).

Stack: TanStack Start + React frontend (Lovable), Python FastAPI backend, OpenAI-compatible LLM client (key, base URL and model from env).

## Part A: Frontend edits (`frontend/src`)

What Lovable produced is solid: an error boundary, sessionStorage history, a paginated sortable table, chart/table toggle, CSV/copy, every state card, and mock mode. The changes needed:

**A1. Contract** (`lib/types.ts`, `lib/api.ts`)
- Remove `RunSqlRequest` and `runSql()`. No `/api/run-sql` endpoint.
- Add `steps?: string[]` to `AskResponse`: plain-Vietnamese reasoning, no SQL jargon.
- Keep `interpretation`, but only for stating defaults (e.g. "Tính trên toàn bộ dữ liệu", meaning the whole date range).

**A2. Remove SQL editing** (`components/shop/SqlBlock.tsx`, `AnswerCard.tsx`, `routes/index.tsx`)
- `SqlBlock` keeps collapsed SQL plus Copy. Remove `editing`/`draft`/`onRun` and the Pencil, Play and Textarea parts.
- Remove `onRunSql`, `runCustomSql`, the `kind: "sql"` turn type, and `StoredTurn.sql` in `index.tsx`.
- Keep the retry transparency ("Đã tự sửa sau N lần thử", research P7/I9).

**A3. Plain-language refine** (`AnswerCard.tsx`, `index.tsx`)
- Under each `ok`/`empty` card, add a small input "Điều chỉnh câu trả lời… (vd: chỉ năm 2026, xem top 10)", next to the existing `suggestions` chips.
- New `onRefine(turnId, text)` in `index.tsx`. It sends `text` as a follow-up with `history` = turns up to and including that card (reuse `historyFor(turns.slice(0, idx + 1), ctxStart)`), so refining an older card uses that card's context.

**A4. Reasoning steps** (new `components/shop/ReasoningSteps.tsx`)
- A collapsible trigger "Xem cách tôi tìm câu trả lời", closed by default, with a numbered list of `steps`. Reuse the `Collapsible` pattern from `SqlBlock`.
- Shown on `ok` and `empty` cards above the SQL block (research I3: show the interpretation, and the main defense against P2).

**A5. Vietnamese UI** (all `shop/*`, `index.tsx`, `__root.tsx`)
- Translate every string: states, buttons, sidebar, loading steps ("Đang hiểu câu hỏi…", "Đang viết truy vấn…", "Đang lấy dữ liệu…"), schema sheet, pagination ("Trang 1/3"), error boundary, 404/error pages. Set `<html lang="vi">` and Vietnamese meta.
- Example chips: Vietnamese versions of the brief's questions, e.g. "Có bao nhiêu khách hàng?", "Top 3 khách hàng chi tiêu nhiều nhất", "Khách hàng chưa từng đặt hàng", "Doanh thu theo tháng năm 2025", "Sản phẩm nào tốt nhất?", "Doanh thu theo thành phố".
- `lib/format.ts`: dates `dd/MM/yyyy`, months `Tháng 10/2025`. Money stays `1,234,000 ₫`. Update `test/format.test.ts`.

**A6. Fix the mock data to match the real schema** (`lib/mock.ts`)
Lovable invented columns (`order_id`, `full_name`, `total_vnd`), cities (Hải Phòng, Huế…), clothing products, and revenue without the paid filter. Rewrite it to use:

Add a clarify mock for "sản phẩm được yêu thích nhất". Remove `mockRunSql`. Fixing the mocks keeps the demo honest and makes them a reference for the backend's response shape.

## Part B: Backend (FastAPI), shaped by RESEARCH.md

```
backend/app/{main,config,llm,prompt,safety,db,pipeline,formatting}.py
backend/tests/, backend/scripts/eval.py, requirements.txt, .env.example
db/readonly_role.sql
```

**B1. Classify first (I1).** One LLM call returns strict JSON:
`{kind: "sql"|"clarify"|"refuse", reason?, sql?, steps[], interpretation?, message?, options[], column_types?, chart?}`
- `steps`, `message`, `options` and `summary` are always in Vietnamese, even for English questions.
- **Clarify-first rule:** clarify when the choice changes the answer, e.g. an undefined metric ("tốt nhất", "được yêu thích nhất", "khách hàng tốt") or an unclear subject. Give 2–4 options (I2), for example "Theo số lượng bán / doanh thu / số khách mua".
- **Don't over-clarify:** a missing time range means all data, and a missing N means top 5. State these defaults in `interpretation`.

**B2. Prompt.** It contains:
- the full `schema.sql`
- a small glossary (I4): revenue = paid only, `quantity × unit_price_vnd`; `products.price_vnd` is the current list price; the data range; the allowed cities and categories
- about 6 pattern examples, none close to a test question: revenue by category, weekly paid orders 2026, average order value per city in a CTE, refuse a write, not_available for suppliers, clarify for "how are sales doing?"

Every example's SQL is run against the DB before it's used (P5). **No RAG.** Verified queries (I5) and thumbs feedback (I6) are future work.

**B3. Read-only, in layers (P9/I8):**
1. The LLM is told to refuse writes.
2. A `sqlglot` validator checks for a single statement whose root is SELECT/WITH, rejects DML/DDL anywhere, and blocks dangerous functions.
3. The `shop_reader` role has SELECT-only grants.
4. Each query runs in `BEGIN READ ONLY` with `statement_timeout 5s`, followed by ROLLBACK.
5. `fetchmany(1001)` caps the rows and sets `truncated` (P8).

**B4. Never crash.** Every failure maps to a status with a Vietnamese message: LLM timeout or bad JSON, missing key, DB down, SQL error, empty or too-long question. A global exception handler always returns JSON.

**B5. Retry (I9).** Up to 2 retries, feeding the Postgres error back to the LLM. Every attempt goes in `attempts`, so the UI says it retried (P7).

**B6. Formatting.** `formatting.py` maps column types to `money/number/date/month/text`, using the LLM hint plus name heuristics, and picks a chart (time + number → line; ≤ 25 categories → bar). A second small LLM call writes the one-line Vietnamese `summary` from the first ~20 rows; it's skipped if that call fails. `/api/schema` returns Vietnamese descriptions.

**B7. Eval set before building (I7, P6).** `scripts/eval.py` runs the 8 test questions plus about 12 of our own (Vietnamese and English, including "sản phẩm được yêu thích nhất" and follow-ups). It prints status, SQL and row count, and is re-run after every prompt change.
